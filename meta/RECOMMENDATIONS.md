# Recommendations

## Most important project

The most important current project is the Android app quality skill suite because it is newly published, structurally validated, and still lacks runtime or scenario-level evidence. Improving evidence there will demonstrate whether the repository’s broader skill-forging and verification practices produce useful outcomes.

## Top priorities

1. Add Android-focused evaluation cases and a baseline rubric.
2. Apply the suite to a minimal sample app when an Android environment is available.
3. Repair measured gaps while preserving focused triggers and progressive disclosure.
4. Keep project continuity files synchronized with meaningful repository changes.

## Quick wins

Add independent JSONL cases for empty, offline, permission denial, process recreation, TalkBack, adaptive layout, and release-gate review. These can be evaluated without building a production application.

## Major opportunities

A portable Android quality harness could connect requirements, skill routing, architecture review, accessibility evidence, runtime checks, and release decisions into one traceable workflow. This is currently **[IDEA]**, not an implemented feature.

## Technical risks

The most significant risks are stale platform-specific guidance, overclaiming quality without evidence, ambiguous skill triggers, and accidental Manus-only coupling. Preserve the documented boundaries and require evidence for promotion.

## What not to prioritize yet

Do not build a large automation platform, add generic Android tutorials, or create templates before repeated evaluations show that they reduce work and improve outcomes.
