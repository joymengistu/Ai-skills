# UI Vision integration map

The user-provided UI Vision Skill is preserved as an attributed source and translated into modular, testable behavior rather than copied into one oversized prompt.

| Source principle | Ai-skills capability | Observable check |
|---|---|---|
| Never design from adjectives alone | `superlative-analysis`, `interaction-design`, `ui-vision` | Adjectives become visible properties and acceptance criteria |
| Professional is not merely beautiful | `ui-vision`, `human-satisfaction`, `product-completeness` | Separate beauty, professionalism, usability, accessibility, and outcome scores |
| Minimalism is subtraction | `ui-vision` | Remove, collapse, contextualize, or justify visible elements |
| Study references without copying | `ui-vision`, `frontier-research`, `design-reference-library` | Record source, observation, abstraction, and what not to copy |
| Measure spacing, controls, type, surfaces, and color | `ui-vision`, `design-system` | Produce tokens and a consistent rhythm rather than random values |
| Assign visual weight and hierarchy | `ui-vision`, `interaction-design` | Primary, supporting, and optional levels remain distinguishable |
| Use restrained buttons, icons, borders, cards, shadows, color, and motion | `ui-vision`, `accessibility` | Component audit finds unnecessary emphasis, inconsistency, and distraction |
| Match information density to the task | `ui-vision`, `human-satisfaction` | First-glance and decision-ease tests pass without emptiness or chaos |
| Hide system complexity | `ui-vision`, `progressive-delivery` | Advanced agents, tools, memory, and status appear through progressive disclosure |
| Remove-20%, smaller, squint, and first-glance tests | `ui-vision`, `dynamic-verification` | Each screen receives reduction and comprehension probes |
| Avoid AI-generated-looking patterns | `ui-vision`, `product-strategy` | Decorative gradients, blobs, badges, oversized headings, and meaningless stats require purpose |
| Screenshot-first decomposition | `ui-vision`, `multimodal-reasoning` | References become measured design principles, not pixel imitation |
| Maintain a visual reference library | `design-reference-library` | References are categorized and include source, strength, pattern, and non-copy guidance |
| Score each screen separately for beauty and professionalism | `ui-vision` | 0–10 score with evidence and a specific path toward improvement |
| Make every visible decision intentional | `ui-vision`, `outcome-completion` | Final review connects visible choices to user goals, states, and evidence |

## Routing rule

For a UI request containing adjectives such as beautiful, professional, minimal, premium, clean, modern, or polished, load the UI Vision skill before generating components. For screenshot-based work, add multimodal reasoning and reference decomposition. For a live product, add product completeness, accessibility, dynamic verification, and requirement traceability.

## Attribution and safety

The original user document is stored at `contributions/UI-Vision-original.txt`. The active skill is an original implementation layer. It does not copy proprietary interfaces, imply endorsement by referenced products, or treat screenshots as permission to reproduce protected assets.
