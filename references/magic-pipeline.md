# The model-agnostic magic pipeline

This is an independent, public-information-derived operating recipe for turning a concise brief into a complete, tested outcome. It is not a reproduction of any proprietary Fable prompt and it cannot guarantee the same result across models.

## Pipeline

| Stage | Required output | Release condition |
|---|---|---|
| 1. Brief compiler | User outcome, explicit requirements, justified inferences, unknowns, assumptions, risks, definition of done | No material requirement is silently discarded |
| 2. Architecture pass | Product/system map, data and state model, tool plan, permission plan, acceptance tests, cost/time budget | Dependencies and risky side effects are visible |
| 3. Vertical slice | Thin end-to-end path through the real stack | A user can complete one valuable journey |
| 4. Staged expansion | Feature ledger, task graph, progress file, checkpoints, clean commits, handoff state | Each stage is independently recoverable |
| 5. Focused delegation | Scoped worker contracts for independent research or artifact work | Expected coverage gain exceeds coordination, token, and conflict cost |
| 6. Dynamic verification | Build-health, live interaction, visual-usability, intent-alignment, accessibility, safety, and operational checks | Evidence exists for each material acceptance criterion |
| 7. Skeptical evaluation | Independent critique, severity, evidence, and repair priorities | No generator self-approval is treated as proof |
| 8. Repair | Reproduce, classify, patch minimally, rerun focused and regression checks | Failure is resolved or honestly escalated |
| 9. Completion gate | Verified/partial/unverified/deferred/blocked report, artifacts, risks, next action | The release claim matches evidence |

## Host contracts

Skills provide guidance. The online host must enforce model selection, tool schemas, permissions, approvals, sandboxing, budgets, cancellation, persistence, event tracing, artifact storage, and recovery. A memory note, plan, or model statement is not authorization or completion evidence.

## Context and handoff

Persist the requirement ledger, task graph, decisions, assumptions, progress, artifacts, tests, evidence, failures, unresolved questions, and next step outside the model context. Reset to a clean context when attention degrades; retrieve only the high-signal state needed for the next decision. Public long-running-agent guidance supports initializer/coding roles, progress files, git, browser automation, and structured handoffs.[1] [2]

## Evaluation dimensions

Measure verified outcome quality, requirement coverage, build health, visual usability, intent alignment, operational readiness, safety, privacy, latency, tokens, cost, tool errors, retries, repair convergence, and human effort. Compare baseline, focused skills, staged harness, evaluator/repair, and delegation routes on held-out tasks rather than inferring causality from a single demo.[3] [4]

## Public evidence

Anthropic's public Fable 5 material supports the relevance of agent harnesses, staged planning, delegation, testing, and vision, while the public system card also documents failure cases. Treat those as bounded product/system-card evidence, not proof of universal superiority.[5] [6]
