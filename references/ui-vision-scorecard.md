# UI Vision scorecard

## Review sequence

1. Define the user's current job, platform, context, and primary decision.
2. Translate adjectives into observable properties and acceptance checks.
3. Decompose references into abstract patterns without copying protected details.
4. Establish hierarchy, density, tokens, states, and interaction rules.
5. Design the simplest coherent option first.
6. Run reduction, squint, first-glance, keyboard, focus, contrast, responsive, and error-recovery checks.
7. Score the result separately and record the highest-leverage repair.

## Screen scorecard

| Dimension | 0–2 | 3–5 | 6–8 | 9–10 |
|---|---|---|---|---|
| Hierarchy | No clear focus | Some emphasis but competition | Primary path is clear | Attention feels effortless |
| Simplicity | Noisy or confusing | Some unnecessary complexity | Mostly restrained | Every visible element earns its place |
| Consistency | Components conflict | Repeated patterns drift | System is coherent | Patterns feel inevitable and learnable |
| Spacing and density | Chaotic or empty | Uneven rhythm | Appropriate density | Information is calm and decision-ready |
| Typography | Hard to scan | Hierarchy is weak | Comfortable and legible | Quietly precise and expressive |
| Controls and states | Unclear or fragile | Basic states missing | Predictable and responsive | Feedback, focus, error, and recovery are excellent |
| Accessibility | Major barriers | Partial support | WCAG-aware implementation | Accessibility is integrated without friction |
| Professional restraint | Decorative or immature | Mixed signals | Mature and purposeful | Nothing fights for attention |
| Originality | Generic imitation | Minor variation | Distinctive choices | Original without novelty theater |
| Intent alignment | Misses the task | Partially serves it | Strongly serves it | Feels designed for the exact user outcome |

## Separate beauty and professionalism

Beauty asks whether the interface is attractive. Professionalism asks whether it is clear, consistent, restrained, usable, accessible, predictable, and mature. Never average these into one flattering number. A beautiful screen with weak usability needs repair, not a higher overall score.

## AI-interface guardrails

Keep complex orchestration, memory, retrieval, browser work, code execution, planning, and verification behind progressive disclosure. Expose the current stage, useful progress, uncertainty, controls, and recovery without giant thinking animations, decorative robot imagery, enormous prompts, noisy status panels, or meaningless metrics.

## Release gate

Do not call a UI polished until the core journey works, primary hierarchy is obvious at first glance, keyboard and focus behavior are usable, contrast and targets are checked, loading/empty/error/success states exist, mobile and large-screen layouts are coherent, and each visible element has a task, state, or brand reason.
