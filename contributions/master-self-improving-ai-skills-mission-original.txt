You are working on the existing AI Skills repository.

Your objective is to transform the repository from a collection of AI skills into a continuously improving, evidence-driven capability system.

Do not optimize for the number of skills.

Optimize for:

INTELLIGENCE
QUALITY
REUSABILITY
COMPOSABILITY
CONTEXT
EXAMPLES
VERIFICATION
LEARNING
SELF-CRITIQUE
HUMAN VALUE

==================================================
CORE VISION
==================================================

Build a system that can:

UNDERSTAND
→ RESEARCH
→ LEARN
→ APPLY
→ OBSERVE
→ CRITIQUE
→ REMEMBER
→ IMPROVE
→ VERIFY

The system should become better at creating and using skills over time.

EVIDENCE-BASED

PART 2 — DESIGN THE IDEAL SKILL
==================================================

Research what makes an AI skill genuinely useful.

Do NOT assume a skill is simply:

"name + instructions."

Design a richer skill specification.

Investigate:

- purpose
- activation conditions
- inputs
- outputs
- principles
- procedures
- examples
- counterexamples
- edge cases
- contextual exceptions
- anti-patterns
- tools
- verification
- benchmarks
- limitations
- uncertainty
- lessons learned
- version history

Create a formal specification.

==================================================
PART 3 — EXAMPLE-DRIVEN INTELLIGENCE
==================================================

Create a framework for teaching skills through examples.

Every important principle should ideally have:

1. POSITIVE EXAMPLE
2. NEGATIVE EXAMPLE
3. BORDERLINE EXAMPLE
4. CONTEXTUAL EXCEPTION
5. TRANSFORMATION EXAMPLE

Example:

PRINCIPLE:
Use restraint in professional UI.

GOOD:
Compact toolbar with clear hierarchy.

BAD:
Every action represented by a giant colorful card.

BORDERLINE:
Large primary CTA on a marketing page.

EXCEPTION:
A primary mobile action may require a larger touch target.

TRANSFORMATION:
Oversized button → compact contextual action.

Do not use examples merely as decoration.

Explain WHY each example represents the principle.

==================================================
PART 4 — CONTEXTUAL REASONING
==================================================

The system must NOT memorize simplistic rules.

Avoid:

"Large buttons are bad."

Instead teach:

"Button size depends on context, importance, frequency,
platform, accessibility requirements, and hierarchy."

Every major principle should distinguish:

GENERAL RULE
CONTEXT
EXCEPTION
TRADEOFF

==================================================
PART 5 — KNOWLEDGE BOUNDARIES
==================================================

Do NOT attempt to make the system pretend to "know everything."

Instead build a structured understanding of:

KNOWN
SUPPORTED
INFERRED
UNCERTAIN
UNKNOWN
OUTDATED
CONFLICTING

The system should know what it does NOT know.

When evidence is insufficient, it should say so.

==================================================
PART 6 — RESEARCH MEMORY
==================================================

Create structured memory for research discoveries.

Each research finding should record:

- claim
- source
- evidence
- date
- confidence
- affected skills
- related concepts
- contradictions
- implications

Do not allow unsupported claims to silently become permanent knowledge.

==================================================
PART 7 — SELF-IMPROVEMENT MEMORY
==================================================

Create a structured learning record.

Each lesson should contain:

OBSERVATION
FAILURE
CAUSE
EVIDENCE
LESSON
ACTION
CONFIDENCE
REGRESSION RISK
NEXT EXPERIMENT

Example:

SKILL:
Professional UI Taste

OBSERVATION:
The evaluator consistently preferred interfaces
with fewer decorative containers.

FAILURE:
The skill previously rewarded card-heavy layouts.

CAUSE:
Visual complexity was incorrectly interpreted as polish.

EVIDENCE:
Multiple reference comparisons.

LESSON:
Professional quality should prioritize hierarchy,
restraint, and contextual density over decoration.

ACTION:
Reduce the weight of decorative complexity.

CONFIDENCE:
Medium-high.

NEXT EXPERIMENT:
Benchmark against additional professional interfaces.

==================================================
PART 9 — SKILL IMPROVEMENT ENGINE
==================================================

Create:

SELF_IMPROVING_SKILL_ENGINE

Input:

EXISTING SKILL

Process:

1. Understand the skill.
2. Establish its intended outcome.
3. Establish benchmarks.
4. Research relevant best practices.
5. Find weaknesses.
6. Generate improvement candidates.
7. Test candidates.
8. Compare against previous version.
9. Detect regressions.
10. Keep only demonstrated improvements.
11. Record the lesson.
12. Update the skill.

Core principle:

LEARN
→ TEST
→ PROVE
→ KEEP

Not:

LEARN
→ ASSUME
→ CHANGE
