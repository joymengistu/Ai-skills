# Micro UI Review Checklist

Run this review against the rendered screen, not only the component source.

| Review area | Pass condition |
|---|---|
| Primary action | One action is easy to find without overpowering every other control. |
| Label economy | Labels are short, specific, and free of unnecessary uppercase or marketing language. |
| Control scale | Toolbar, tab, navigation, filter, and secondary controls are no larger than their task requires. |
| Whitespace | Controls have room to breathe; compactness has not produced clutter. |
| Grouping | Related actions are grouped; unrelated controls are separated; decorative dividers are sparse. |
| Information efficiency | Repeated data uses rows or compact structures where appropriate; cards justify their presence. |
| Icon clarity | Icon-only actions are familiar, labelled for assistive technology, tooltipped, and keyboard reachable. |
| Responsive behavior | The core task and primary action survive on narrow screens; secondary actions collapse safely. |
| State feedback | Hover, focus, pressed, disabled, loading, error, and success states remain clear and restrained. |
| Anti-slop check | No giant gradient CTA, unnecessary glass, oversized pills, exaggerated shadow, loud glow, or empty-space filler remains. |

## Final question

Ask: **Would a focused person working quickly feel that every control is exactly where it should be, exactly as large as it needs to be, and no larger?** If not, simplify the hierarchy before adding decoration.
