# Design reference library

Collect references by component and state: navigation, buttons, inputs, composers, sidebars, settings, command palettes, tables, dashboards, mobile navigation, loading, empty, error, agent activity, research, files, and productivity surfaces.

For each reference record the source, date, screenshot or URL, what works, the pattern it demonstrates, the context where it works, and what must not be copied. Do not treat a screenshot as a specification. Decompose it into layout, spacing rhythm, type hierarchy, control proportions, density, color roles, surfaces, motion, and interaction patterns.

Extract approximate design tokens rather than duplicating exact values: spacing scale, content width, control heights, radius, icon size, sidebar dimensions, typography scale, density, and semantic color hierarchy. Validate tokens against the product's users, platform, accessibility needs, and brand.

Use references to generate principles and alternatives, not clones. Compare at least one restrained option and one expressive option, then choose based on user outcome, task clarity, consistency, accessibility, and originality. Keep provenance for every imported image, font, icon, component, or code sample.

## Operational deepening

Use this Skill to improve **abstracting useful principles from visual references**. Load it only when that outcome is relevant; do not activate it for unrelated work. The main review surface is layout, hierarchy, tokens, interaction, originality, accessibility, and screenshot limits.

### Execute

1. Inspect the request, current artifact, context, constraints, and permissions before choosing a procedure.
2. Separate explicit requirements from reversible assumptions, optional ideas, and unknowns. Preserve the user’s goal and ask one focused question when ambiguity changes architecture, cost, privacy, safety, authority, or likely value.
3. Choose the smallest sufficient workflow. Produce an observable intermediate artifact, then verify the real result against acceptance criteria and the highest-risk edge states.
4. If the result fails, reproduce the failure, classify the smallest cause, patch narrowly, rerun focused and regression checks, and record what remains uncertain.

### Evidence and boundaries

Treat generated output as a candidate, not proof. Record the evidence source, confidence, freshness, and scope of each material claim. Do not grant permissions, change safety boundaries, retain sensitive memory, or declare completion merely because this Skill was loaded. Coordinate with the host runtime for approvals, budgets, traces, isolation, and external effects.
