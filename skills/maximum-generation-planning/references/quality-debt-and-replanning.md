# Quality Debt and Evidence-Driven Replanning

## Quality debt

Quality debt is an **observed, material gap** between the planned experience promise and the current artifact. It must name the evidence and a likely smallest cause.

| Observed gap | Evidence | Likely smallest repair |
|---|---|---|
| First screen looks like a generic card dashboard. | Target-width screenshot shows repeated equal-weight cards and no primary task. | Rework hierarchy and information grouping before adding visual effects. |
| Exploration world feels directionless. | Playtest/screenshot has no readable landmark or discovery route. | Add one deliberate focal landmark and compose the approach path. |
| Tool action feels inert. | Interaction capture shows state changed with no visible acknowledgement. | Add concise state feedback; do not add unrelated animation. |
| Generated collection feels repetitive. | Output comparison exposes repeated layout/geometry. | Constrain variation around meaningful composition parameters. |

## Replan only when evidence changes the graph

Replan a milestone if a verifier fails, a precondition is false, a quality debt cannot be repaired within the current milestone, evidence reveals the wrong dependency, or a constraint changes value/risk. Preserve completed evidence and modify only the affected nodes and descendants.

Do not replan because the agent is bored, a trend seems fashionable, or an untested improvement sounds impressive.

## Quality-debt priority

Prioritize high-impact, high-confidence, dependency-critical debt first. Defer a low-impact enhancement when it competes with clarity, accessibility, stability, or the promised user outcome. Every deferred item needs a reason and review condition.
